# JobFetch

**Превращает разрозненные сигналы о найме в вакансии, которые удобно читать.**

[Сайт и вакансии](https://job-ftch.aiguild.space/ru/jobs) · [Telegram-канал](https://t.me/ai_engineer_jobs) · [Документация](https://letya999.github.io/job_ftch/) · [English](README.md)

JobFetch — открытый асинхронный конвейер для сбора вакансий из Telegram, карьерных сайтов, RSS и API. Он извлекает данные из разных форматов, приводит их к типизированной записи, объединяет дубли, оценивает релевантность и публикует подходящие результаты. Система предназначена для сообществ и команд, которым нужен собственный поток вакансий и контроль над его источниками.

```text
источники → сбор → извлечение → нормализация → дедупликация → оценка → публикация
```

## Запустить локальный пример

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/letya999/job_ftch.git
cd job_ftch
uv sync
uv run job_ftch eval --fixture classification
```

Команда проверяет локальный тестовый набор: она не обращается к живым сайтам и ничего не публикует. Для запуска своего набора источников начните с [руководства](docs/quickstart.md) и проверьте конфигурацию командой `uv run job_ftch validate --config tenant.yaml`.

| Эксплуатация | Состояние в PostgreSQL, диагностика и OpenObserve |

## Выбрать подключение LLM

Для начала достаточно токена и OpenAI-compatible endpoint. Остальные компоненты подключаются по необходимости:

| Режим | Что требуется | Как работает |
| --- | --- | --- |
| Прямой compatible API | Endpoint, модель и API-токен | Обычные inline-вызовы; очередь и телефон не нужны |
| Compatible API через очередь | PostgreSQL, worker и extra `llm-queue` | Сохранённые запросы, общие бюджеты и отложенное продолжение |
| CLIProxyAPI с дополнительной защитой | Профиль CLIProxyAPI с `gateway: cliproxy` и `execution: queued` | Привязка сессии запуска, джиттер, cooldown, circuit breaker и опциональный итоговый отчёт |
| CLIProxyAPI через домашнюю сеть | Предыдущий режим, Tailscale и Android как exit node | Обязательный выход через закреплённый телефон; при его недоступности отправка приостанавливается |

Очередь использует PostgreSQL, Redis не требуется. Одна логическая сессия живёт в пределах запуска и его отложенных продолжений, включая перезапуски процесса. У каждой вакансии остаются отдельные prompt и идентификатор запроса: общая привязка не смешивает переписки. Новые механизмы CLIProxy не включаются для прямого API.

Настройки, подключение Android и команды восстановления — в [руководстве по очереди и домашнему выходу](docs/operations/llm-queue-and-home-egress.md). Регулирование нагрузки не расширяет квоты провайдера и не гарантирует отсутствие блокировок аккаунта.

## Развернуть и обслуживать

- [Production-развёртывание](docs/deploy.md): контейнеры, постоянное состояние и readiness.
- [Очередь LLM](docs/operations/llm-queue-and-home-egress.md): ожидающие запросы, cooldown и паузы оператора.
- [Восстановление публикаций](docs/deploy.md#сверка-неопределённой-публикации): проверка потерянного ответа Telegram перед повторной отправкой.
- [Релизный чеклист](docs/release_checklist.md): тесты, проверка секретов, CI и сверка версий.

Храните API-токены, OAuth credentials, Telegram-сессии и состояние Tailscale вне Git и контекста сборки образов. Перед обновлением сохраняйте БД и приватное состояние. Сохраняйте набор активных Compose overlays: запуск только базового файла не сохраняет опциональную очередь и домашний маршрут.

Неизвестный исход LLM-запроса и неизвестная доставка Telegram — разные состояния. Восстановление связи с моделью не подтверждает отправку карточки. Используйте соответствующую процедуру восстановления; хранилище запросов и журнал публикаций защищают от слепого автоматического повтора.

## Проверить изменения

```bash
just code-verify
just tests-all
just docs-verify
```

Команды проверяют код и типы, тесты без сети и документацию. Интеграционные тесты очереди используют отдельную временную PostgreSQL БД; в CI она поднимается автоматически. Optional extras, browser checks и полный релизный gate описаны в [CI/CD](docs/operations/ci-cd.md).

## Похожие решения

Это самостоятельные проекты с пересекающимися задачами, а не части JobFetch:

| Проект | Основная задача |
| --- | --- |
| [Job Seek](https://github.com/colophon-group/jobseek) | Поиск по карьерным сайтам и ATS, отслеживание откликов |
| [freehire](https://github.com/strelov1/freehire) | Открытый агрегатор и поиск IT-вакансий |
| [JobSpy](https://github.com/speedyapply/JobSpy) | Python-библиотека для сбора вакансий с крупных площадок |
| [career-ops](https://github.com/career-ops-hq/career-ops) | Локальный помощник кандидата: оценка вакансий, CV и учёт откликов |

Фокус JobFetch — на настраиваемом пути **источник → данные и подтверждения → оценка → публикация**, в том числе для Telegram-сообщества. Основное production-развёртывание — Telegram-бот; надёжность отдельных сайтов проверяется отдельно и не следует автоматически из зелёного CI.
