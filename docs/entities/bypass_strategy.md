# BypassStrategy (Стратегия обхода защит)

## Что это такое

BypassStrategy — это слой абстракции над HTTP-клиентом или
браузером, который маскирует автоматизированные запросы
(ботов) под запросы реальных людей.
Разные сайты имеют разную степень антибот-защиты, и
`BypassStrategy` позволяет системе динамически выбирать
подходящий инструмент для обхода.

## Зачем это нужно и ПОЧЕМУ так устроено

Сегодня карьерные сайты агрессивно защищаются от парсинга
(скрапинга) с помощью сервисов вроде Cloudflare, Datadome,
Akamai и hCaptcha.
Обычный скрипт на Python (`requests.get()` или
`httpx.get()`) моментально получит ошибку 403 Forbidden или
требование решить капчу, так как защита легко детектирует
несоответствие TLS-отпечатков (TLS fingerprinting) или
отсутствие полного браузерного окружения.

Дизайн-решение заключается во внедрении *Политики эскалации
(Adaptive Escalation)*.
Мы не используем самые тяжелые инструменты сразу.
Запуск полноценного браузера занимает много памяти и
времени.
Система начинает с самых дешёвых способов и "эскалирует"
стратегию только при получении 403 ошибки.
Выбранная успешная стратегия кэшируется в `Store` для
конкретного домена, чтобы в следующий раз сразу использовать
правильный подход.

## Как это работает изнутри

Protocol `BypassStrategy` в `contracts.py` предоставляет
методы для модификации как простых HTTP-клиентов, так и
headless-браузеров:

```python from typing import Protocol, Any, runtime_checkable

@runtime_checkable class BypassStrategy(Protocol):
    async def apply_http(self, client: Any) -> Any:
        """Применить обход к HTTP клиенту (например, подменить httpx на curl_cffi)."""

    def apply_browser_args(self, kwargs: dict[str, Any]) -> dict[str, Any]:
        """Добавить аргументы скрытности к Playwright (флаги, прокси)."""

    async def apply_page(self, page: Any) -> None:
        """Инжектировать stealth-скрипты в созданную страницу браузера."""
```

Если сайт прост, мы используем модифицированный HTTP-клиент.
Если сайт сложный — мы запускаем Playwright (браузер) и
применяем методы `apply_browser_args` и `apply_page`.

## Реализации по возрастанию сложности/стоимости

1. `noop` (No Operation)

Не делает ничего, использует стандартный `httpx`.
Подходит для сайтов без защиты (REST API, RSS-ленты, очень
простые сайты).
Самый быстрый вариант с нулевым оверхедом.

2. `curl_impersonate`

Использует библиотеку `curl_cffi`, которая эмулирует TLS
fingerprint реального браузера (например, Chrome 120).
Позволяет обойти базовые проверки Cloudflare на уровне
рукопожатия, оставаясь при этом в рамках одного быстрого
процесса (без запуска реального браузера).
Подходит для ~60% сайтов.

3. `playwright_stealth`

Запускает реальный Chromium через Playwright, предварительно
внедряя плагины (stealth), которые удаляют флаги
`webdriver`, подменяют свойства `navigator` и эмулируют
человеческое поведение.
Требует бинарников браузера (~300MB) и работает значительно
медленнее.
Подходит для ~90% защищенных сайтов.

4. `cloak_browser`

Самый продвинутый режим, использующий специализированный
антидетект-браузер.
Используется для самых жестких энтерпрайз-защит (например,
HH.ru, LinkedIn), где обычный Playwright-stealth не
справляется.

5. `proxy_rotator`

Обертка-декоратор над любой из вышеперечисленных стратегий.
На каждый запрос она подставляет новый прокси-сервер
(IP-адрес).
Решает проблему Rate Limiting (ограничения по частоте
запросов с одного IP), но не спасает от TLS-фингерпринтинга.

## Политика эскалации (Пример работы)

1. `CareerSiteSource` хочет спарсить `careers.company.com`.

2. Запрашивает у `Store` стратегию. Кэша нет.

3. Пробует `noop` -> получает 403 Forbidden.

4. Пробует `curl_impersonate` -> получает 200 OK.

5. Сохраняет в `Store`: `domain: "careers.company.com" → стратегия: "curl_impersonate"`.

6. При следующем запуске пайплайна сразу используется `curl_impersonate`.

## Типичные ошибки и что нельзя делать

1. **Использовать playwright_stealth для всего подряд.**

Запуск инстанса браузера требует в десятки раз больше памяти
и процессорного времени, чем обычный HTTP-запрос.
Если сайту достаточно `curl_impersonate`, использование
браузера — это пустая трата инфраструктурных ресурсов.

2. **Игнорировать управление ресурсами (context managers).**

Браузеры (особенно Playwright) плодят процессы ОС.
Если вы не закрываете `session`, `page` или не используете
`async with`, у вас в системе накопятся зомби-процессы,
которые съедят всю память сервера (OOM).

3. **Протекание логики обхода в доменные узлы.**

Обход защит (Bypass) должен применяться исключительно на
уровне Источников (Source), конкретно в
`infrastructure/scrapers`.
Ни один обрабатывающий узел (`Stage`) не должен ничего знать
о TLS, Cloudflare или прокси.

## Связи с другими сущностями

- [Source](source.md) — источники (особенно `CareerSiteSource`) используют стратегии для скачивания HTML.

- [Store](store.md) — используется для сохранения успешных стратегий для конкретных доменов (Adaptive Escalation).
