# Job Group Store

## Что это такое

`JobGroupStore` — это специализированное хранилище (база
данных), которое отвечает исключительно за поиск, создание и
слияние (merge) дубликатов вакансий в единую группу
(`JobGroup`).

Этот интерфейс не хранит сырые тексты вакансий.
Его основная задача — оперировать сущностью `JobGroup`,
которая объединяет один или несколько `JobRecord`
(конкретных постов) на основе их криптографических
отпечатков (fingerprints) или канонических URL.

## Зачем это нужно и ПОЧЕМУ так устроено

Одна и та же вакансия может быть опубликована компанией на
их официальном сайте, продублирована на HH.ru, а затем
репостнута в трех разных Telegram-каналах.
С точки зрения пайплайна, это 5 разных сырых текстов
(`RawItem`).
Но с точки зрения кандидата (пользователя) — это одна и та
же позиция, и он не хочет видеть 5 одинаковых карточек в
своей ленте.

Дизайн-решение (JobAggregationNode + JobGroupStore)
заключается в том, что:
1. `JobAggregationNode` (узел пайплайна) вычисляет для
каждой новой вакансии уникальный отпечаток (fingerprint)
на основе названия, компании и локации (например,
`hash("Python Developer | Yandex | Moscow")`).
2. Узел обращается к `JobGroupStore` с этим отпечатком.
3. Если `JobGroupStore` находит существующую группу с
таким отпечатком, новая вакансия "привязывается" к этой
группе.
4. Если нет — создается новая группа.

Разделение обычного `JobPersistenceBackend` (где лежат
вакансии) и `JobGroupStore` позволяет оптимизировать базу
данных под сверхбыстрый поиск по отпечаткам и URL, не
замедляя обычные запросы на чтение вакансий.

## Как это работает изнутри

Интерфейс определен в `contracts.py`:

```python
class JobGroupStore(Protocol):
    async def create(self, job: JobRecord) -> JobGroup:
        """Создает новую группу из вакансии."""

    async def merge(
        self, group_id: str, job: JobRecord, merge_confidence: float = 1.0
    ) -> JobGroup:
        """Добавляет вакансию в существующую группу."""

    async def find_by_fingerprint(
        self, fingerprint: str
    ) -> JobGroup | None:
        """Ищет группу по вычисленному хэшу."""
        
    async def find_by_url(
        self, canonical_url: str
    ) -> JobGroup | None:
        """Ищет группу по каноническому URL (например, greenhouse.io/...)."""
```

Слияние (Merge) происходит на уровне базы данных.
Когда вызывается `merge()`, `JobGroupStore` должен:
- Обновить массив `source_links` в группе (добавить
новую ссылку).
- При необходимости, обновить общую зарплатную вилку
группы, если новый источник дал более точные цифры.
- Установить связи (Foreign Keys) для новой `JobRecord`.

## Важность Canonical URL

Матчинг по `fingerprint` (название + компания) не всегда
надежен, так как компании могут менять названия позиций в
разных каналах ("Senior Backend" vs "Backend Developer").

Поэтому `JobGroupStore` поддерживает поиск по
каноническому URL.
Например, если в Telegram-посте найдена ссылка
`https://boards.greenhouse.io/openai/jobs/123`, пайплайн
сначала проверяет `find_by_url()`.
Если такая вакансия уже выкачивалась напрямую с сайта
Greenhouse, Telegram-пост моментально сливается с ней, даже
если их текстовые описания различаются.

## Типичные ошибки и что нельзя делать

1. **Использовать Store вместо JobGroupStore.**

В пайплайне есть обычный `Store`, который тоже делает
дедупликацию (через `DedupNode`).
Разница критична:
- `Store` (DedupNode) отбрасывает ПОЛНЫЕ дубликаты (один и
тот же пост в одном и том же канале). Эта вакансия даже не
доходит до LLM.
- `JobGroupStore` (JobAggregationNode) работает в конце
пайплайна. Он объединяет семантические дубликаты (разные
тексты об одной и той же должности).

2. **Забывать передавать JobGroupStore в Runtime Adapter.**

Если вы создаете инстанс приложения, вы должны
инициализировать реализацию `JobGroupStore` (например,
`PostgresJobGroupStore`) и передать ее узлу агрегации.
Без этого узлу негде будет искать старые отпечатки.

3. **Слишком агрессивный merge.**

Если ваш алгоритм генерации `fingerprint` слишком
простой (например, только по названию компании),
`JobGroupStore` сольет все открытые вакансии "Яндекса" в
одну гигантскую группу.
