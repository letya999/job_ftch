# ML & Infrastructure Providers

## Что это такое

`job_ftch` использует портовую архитектуру (Ports and Adapters).
Ядро пайплайна содержит множество интерфейсов (Protocols)
для специфических задач, которые требуют подключения внешних
библиотек, баз данных или тяжелых нейросетей.

Эти интерфейсы объединены в общую категорию провайдеров.
Они делятся на две логические группы: **ML/Text
провайдеры** (обработка естественного языка) и
**Инфраструктурные провайдеры** (метрики, прокси).
Все они регистрируются в реестре плагинов и передаются в
пайплайн при сборке.

## Зачем это нужно и ПОЧЕМУ так устроено

Если бы ядро `job_ftch` импортировало `torch`, `sentence-transformers`
или библиотеки для работы с Prometheus, оно бы весило
гигабайты и было бы несовместимо с легковесными
serverless-средами.

Дизайн-решение (Инверсия зависимостей): ядро только
"объявляет" интерфейсы.
Разработчик может установить легкий плагин (например,
вызывающий платное API OpenAI для эмбеддингов) или тяжелый
локальный плагин (скачивающий 5 ГБ весов локальной модели).
Ядро работает с ними одинаково.

## Категория 1: ML & Text Провайдеры

Эта группа интерфейсов отвечает за обработку текста, минуя
генеративные LLM.
Их задача — быть быстрыми и дешевыми.

### 1. EmbeddingProvider
Отвечает за превращение текста вакансии или резюме в
математический вектор (список `float`).

```python
class EmbeddingProvider(Protocol):
    async def embed(self, texts: list[str]) -> list[list[float]]: ...
```
**Использование:** Применяется в `SemanticPrefilterNode` для
сравнения векторов вакансий и `CandidateProfile` до вызова
экстракции. Позволяет дешево отсеивать абсолютно нерелевантный
мусор.

### 2. ClassifierProvider
Быстрая ML-модель для классификации текста.

```python
class ClassifierProvider(Protocol):
    async def classify(self, text: str) -> ClassificationResult: ...
```
**Использование:** Применяется в `PostTypeClassificationNode`
для мгновенного определения: это вакансия, резюме или спам.
Гораздо дешевле, чем просить LLM ответить на этот вопрос.

### 3. Normalizer
Служба для приведения ролей, грейдов и навыков к единой
онтологии (стандарту).

```python
class Normalizer(Protocol):
    def infer_role_family(self, title: str) -> str | None: ...
    def infer_seniority(self, title: str) -> str | None: ...
```
**Использование:** Превращает хаотичные заголовки вроде
"Senior Backend Engineer (Python)" в стандартизированные
тэги (роль: `backend`, грейд: `senior`), чтобы UI мог
строить фасетные фильтры.

### 4. LanguageDetectorPort & TranslatorPort
Определение языка вакансии и машинный перевод.

```python
class LanguageDetectorPort(Protocol):
    def detect(self, text: str) -> str: ...
```
**Использование:** Позволяет пайплайну отфильтровать
вакансии на языках, которые не поддерживает текущий тенант,
или перевести их на лету (через `TranslatorPort`).

### 5. CrossEncoderPort
Модель для Reranking-а результатов поиска.

Она принимает поисковый запрос (например, "Python Developer")
и список найденных вакансий, и пересортировывает их,
используя модель-кроссэнкодер для оценки семантической
близости. Это улучшает релевантность поиска на клиенте.

## Категория 2: Инфраструктурные Провайдеры

Эти интерфейсы скрывают сложность сетевого взаимодействия
и мониторинга.

### 1. ProxyManager
Абстракция для пула прокси-серверов.

```python
class ProxyManager(Protocol):
    def get_proxy(self) -> str | None: ...
```
**Использование:** `CareerSiteSource` запрашивает новый
прокси перед каждым HTTP-вызовом к карьерным сайтам, чтобы
обойти rate limits. Плагины могут реализовать ротацию,
backoff и удаление "забаненных" прокси из пула.

### 2. MetricsExporter
Экспорт бизнес-метрик пайплайна во внешние системы.

```python
class MetricsExporter(Protocol):
    async def observe_run(
        self, summary: RunSummary, *, tenant_id: str
    ) -> None: ...
```
**Использование:** Вызывается после `pipeline.run()`.
Плагин `PrometheusExporter` или `DatadogExporter` забирает
данные о количестве ошибок, скачанных и отброшенных
вакансиях, и отправляет их в дашборды.

### 3. StoreConnector
Низкоуровневый KV-интерфейс для работы `Store`.

Вместо того чтобы заставлять `Store` реализовывать логику SQL,
`Store` является лишь бизнес-адаптером, который под капотом
дергает `StoreConnector` (set, get, set_contains). Это
позволяет легко менять Redis на SQLite без изменения логики
дедупликации.

## Типичные ошибки и что нельзя делать

1. **Реализовывать парсинг внутри провайдеров.**

Провайдеры (особенно `Normalizer` и `LanguageDetector`)
должны быть "чистыми" функциями.
Они не должны делать HTTP-запросы (кроме API-моделей) или
читать файлы в рантайме.
Все словари онтологий должны загружаться в память при
старте приложения (в фабрике плагина).

2. **Отказываться от асинхронности в ML-провайдерах.**

Даже если ваш `EmbeddingProvider` вызывает локальную PyTorch
модель, которая блокирует поток, оберните этот вызов в
`asyncio.to_thread()`. Иначе один вызов модели полностью
остановит (заблокирует) event loop всего FastAPI-сервера.
