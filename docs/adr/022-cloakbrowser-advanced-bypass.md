# ADR 022: Использование CloakBrowser для обхода продвинутых анти-фрод систем

**Date**: 2026-06-09
**Status**: ACCEPTED

## Context

При масштабировании пайплайна агрегации вакансий на крупные ресурсы (например, Ozon.tech, Glassdoor, Indeed) мы столкнулись с жесткими блокировками со стороны энтерпрайз-решений защиты от ботов (Cloudflare Bot Management, Kasada, PerimeterX).

Первоначальные решения:
1. Чистый `httpx` — блокировался по TLS-отпечаткам (JA3).
2. Подмена TLS через `curl_cffi` — помогала против базовых защит, но проваливалась на JS-челленджах.
3. Playwright с инъекциями JS (`playwright-stealth`) — успешно решал простые челленджи, но обнаруживался на глубоких проверках аппаратуры (WebGL, Canvas, AudioContext).

## Decision

Мы внедряем использование **CloakBrowser** (поверх пакета `cloakbrowser`) как ультимативного механизма обхода в рамках архитектуры `BypassStrategy` (`CloakBrowserBypass`).

CloakBrowser — это модифицированный на уровне исходного кода (C++) бинарник Chromium. 
Вместо того чтобы скрывать автоматизацию через инъекции JavaScript в каждую страницу (что легко детектируется), он вносит случайные изменения в математику отрисовки и нативно маскирует флаги автоматизации. 

Интеграция реализована так, что пакет автоматически скачивает нужный бинарник в кэш пользователя (`~/.cloakbrowser`) при первом запуске, что освобождает нас от необходимости хранить бинарники в репозитории.

## Consequences

*   **Positive:** Радикально повышена проходимость скраперов (100% успех на Ozon.tech, Glassdoor). Нет необходимости писать сложные скрипты обхода "руками".
*   **Negative:** Увеличение потребления RAM/CPU при использовании этого Bypass (запускается полноценный браузер). Требуется время на загрузку ~150 МБ бинарника при первом холодном старте.
*   **Limitation:** CloakBrowser подделывает "железо", но не скрывает IP-адрес сервера. Для сайтов с агрессивной защитой по IP (например, Indeed) `cloak` должен комбинироваться с резидентными прокси (`ProxyRotatorBypass`).
