# 102 — Неопределённая доставка Telegram

**Status**: ACCEPTED
**Date**: 2026-10-27

## Контекст

Telegram Bot API не предоставляет ключ идемпотентности для отправки. Если ответ
потерян после принятия сообщения, повтор может создать дубль; запись отправки до
вызова API может вместо этого потерять вакансию. ADR-053 и предложенный ADR-090
не гарантируют exactly-once для такого внешнего API.

## Решение

Для отправок с поддержкой durable outbox до вызова транспорта создаются записи
`uncertain`, отдельно по идентификатору вакансии и нормализованному URL и с
учётом tenant и целевого канала. Записи одной попытки связываются случайным
идентификатором. Наличие неопределённой записи запрещает автоматический повтор;
подтверждённая доставка сохраняет настоящий receipt и переводит записи в
`delivered`. Явный отказ карточки, Telegram flood-wait или запрет канала
освобождают только принадлежащие попытке записи. Неизвестный результат требует
ручной сверки; предварительное резервирование не считается доставкой.

Старый общий журнал при первом запуске закрепляется за первым каналом как
неизменяемый снимок. Новые идентификаторы дополнительно записываются в журнал
канала. UTM-параметры не участвуют в сравнении URL; прочие параметры сохраняются.
Неопределённые попытки видны в readiness и доступны оператору через команду
сверки. Чтение и сверка ограничены тенантом.

## Ограничения

Реальная exactly-once доставка невозможна без идемпотентности транспорта.
Сбой до отправки тоже оставит запись для сверки. Сверка выполняется только
после прекращения соответствующей активной отправки и проверки канала. Канальные
алиасы одного и того же Telegram чата должны оставаться стабильными. Старые
записи общего журнала не содержат целевой канал, поэтому закрепление за первым
каналом является миграционным допущением. Хранилища без возможности outbox
сохраняют прежнюю совместимость и не дают этой гарантии.
