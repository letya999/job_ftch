## Context (read before implementing)

The project is a hexagonal Python job scraper (`job_ftch/`). Key paths:
- `job_ftch/config.py` — `Settings` dataclass with all env-driven defaults
- `job_ftch/domain/tenant.py` — `TenantConfig` dataclass (YAML-loaded per-tenant settings)
- `job_ftch/application/builder.py` — wires store/sink/nodes; `build_output_sinks()` conditionally adds posting sink
- `job_ftch/adapters/telegram_bot/bot.py` — all bot commands; `handle_update()` currently ignores documents
- `job_ftch/adapters/telegram_bot/api.py` — FastAPI routes for webhook
- `job_ftch/adapters/source_inputs.py` — `build_source_spec_from_input(link)` auto-detects TG vs URL
- `job_ftch/adapters/profile_inputs.py` — `build_candidate_profile_from_payload(user_id, profile_id, payload)` — entry point for profile creation
- `job_ftch/application/tenant_runner.py` — `add_source_spec()`, `save_candidate_profile()`, `set_active_candidate_profile()`

Tests live in `tests/`. Run: `python -m pytest tests/ -x -q`  
Lint: `ruff check . && mypy job_ftch/`

### P1-B: Default store → postgres (with sqlite fallback)

**Goal:** Sources and profiles added at runtime survive restart. Currently `store_backend = "memory"` in two places; that's the bug.

**What to change:**

**File: `job_ftch/config.py`**
- Line 21: change `store_backend: str = "memory"` → `store_backend: str = "sqlite"`
- Keep `store_path: Path = Path(".runtime/job_ftch.db")` as-is (sqlite uses it when no DSN)
- When `STORE_DSN` env var is set (postgres connection string), the existing `create_store_with_fallback` already switches to postgres automatically — no code change needed there
- Add docstring/comment on `store_backend` explaining the three values: `"memory"` (tests only), `"sqlite"` (self-hosted default), `"postgres"` (production — requires `STORE_DSN`)

**File: `job_ftch/domain/tenant.py`**  
- Line 83: change `store_backend: str = "memory"` → `store_backend: str = "sqlite"`
- Line 84: `job_group_store_backend: str = "sqlite"` — already correct, keep

**File: `job_ftch/infrastructure/stores/__init__.py` or `sql_adapter.py`** (whichever exports `create_store_with_fallback`)  
- Verify: when `settings.store_backend == "postgres"` AND `settings.store_dsn` is not None, the factory uses `postgres.py`. If not already handled, add this routing.
- The fallback: if postgres DSN fails to connect at startup, fall back to sqlite and log a warning. This should already be in `create_store_with_fallback` — confirm, don't break it.

**Tests:**

## PRIORITY 2 — MVP feature gaps

### P2-A: Resume file upload → profile (ProfileArchitect)

**Goal:** User sends a document (PDF/DOCX/TXT) or pastes raw text to the bot → bot extracts a `CandidateProfile` → saves and activates it. This is the headline MVP feature.

**Where to add:**

**File: `job_ftch/adapters/telegram_bot/bot.py`**

1. In `handle_update()`, after the `text = message.get("text")` block, add document handling:
   ```
   document = message.get("document")
   if document and not isinstance(text, str):
       await self.handle_document(document, chat_id=chat_id, user_id=user_id)
       return
   ```
2. Add `async def handle_document(self, document: dict, *, chat_id: int, user_id: int) -> None:`
   - Download file via Telegram Bot API `getFile` + `downloadFile` (use `self._sender` or a new helper)
   - Extract text from downloaded bytes: TXT → decode utf-8; PDF → use `pdfminer.six` or `pypdf`; DOCX → use `python-docx`
   - Call `build_profile_from_resume_text(text, user_id=str(user_id))` (new function, see below)
   - Save + activate profile via existing `runner.save_candidate_profile()` + `runner.set_active_candidate_profile()`
   - Reply: "Profile created from your resume. Active: <profile_id>"

**File: `job_ftch/adapters/profile_inputs.py`** — add new function:
```
def build_profile_from_resume_text(text: str, *, user_id: str, profile_id: str | None = None) -> ManagedCandidateProfile:
```
Heuristic extraction (no LLM dependency for MVP):
- `name`: first non-empty line
- `summary`: first 300 chars of text
- `target_roles`: scan for common role keywords (Engineer, Analyst, Developer, Manager, Lead, Architect, Scientist, Designer) — collect unique matches  
- `required_skills`: scan for known tech keywords list (Python, SQL, Java, Go, TypeScript, React, Postgres, Kubernetes, Docker, Spark, dbt, Kafka, Airflow, etc.) — collect unique matches
- `languages_of_interest`: detect ru/en/kk from script distribution
- `relevance_threshold`: default 0.3

Use `CandidateResumeSnapshot(raw_text=text[:5000])` to attach the original.

**New optional dependency** (add to `pyproject.toml` extras, not core):
```
[project.optional-dependencies]
resume = ["pypdf>=4.0", "python-docx>=1.1"]
```

**Tests:** add `tests/test_profile_from_resume.py` — test heuristic extraction with a sample resume text string. No file I/O needed in tests.

**Commit:** `feat(bot): resume file upload → CandidateProfile via heuristic extraction`

### P2-B: Bulk source add `/addsources`

**Goal:** Paste a multiline list of URLs / `@channels` → all added in one command.

**File: `job_ftch/adapters/telegram_bot/bot.py`**

Add command `/addsources <tenant_id>` followed by newline-separated links in `arg_text`:
```
/addsources my_tenant
https://hh.ru/employer/123
@ai_jobs_ru
@data_jobs_kz
https://karriera.kz/vacancies
```

Implementation:
- Parse: `lines = [l.strip() for l in arg_text.split('\n') if l.strip() and not l.strip().startswith('/')][1:]` (skip first line = tenant_id)
- Actually: `args[0]` = tenant_id, remaining `arg_text` after first space = the multiline blob. Split on newlines.
- For each line, call `build_source_spec_from_input(link, ...)` then `runner.add_source_spec(...)` — already works per-item (P1-A already uses this). Just loop.
- Collect results: successes and failures (invalid URL format)
- Reply summary: "Added 3/4 sources. Failed: [bad_url] (unknown format)"

**No new logic needed** — just loop over existing single-add path.

**Tests:** add test in `tests/test_bot_addsources.py` — mock `add_source_spec`, verify it's called N times.

**Commit:** `feat(bot): /addsources command for bulk source registration`

### P2-C: Notification mode config `/setnotify`

**Goal:** User sets per-item or digest(N) mode from bot. Currently only controlled by env; no runtime switch.

**File: `job_ftch/adapters/telegram_bot/bot.py`**

Add command `/setnotify <tenant_id> <mode>` where mode:
- `immediate` — notify per job as soon as it passes pipeline (current `posting_sink` per-item behaviour)
- `digest <N>` — buffer N jobs, then send a digest (uses existing `format_job_digest`)

Implementation:
- Save mode to store under key `"config:notify_mode"` and `"config:notify_batch_size"`  
- On `TenantRunner._run_pipeline_for_source()` completion (or `run_tenant()`), read mode from store and route accordingly
- For `digest` mode: accumulate emitted `JobRecord` list in run summary → call `format_job_digest` once → send

This is the thinnest viable version: no state between runs, digest is per-run-completion not time-based.

**File: `job_ftch/application/tenant_runner.py`** — after `run_tenant()` finishes and `summary.emitted > 0`:
- Read `"config:notify_mode"` from store
- If `"digest"`: call `TelegramBotSender.send_message(digest_text)` (inject sender or fire via runner callback)

For MVP this can be a simple `notify_mode: str = "immediate"` field in `TenantConfig` (YAML-settable) without full runtime mutation. Bot command sets it in store, runner reads from store at run start.

**Commit:** `feat(bot): /setnotify command for immediate vs digest notification mode`
